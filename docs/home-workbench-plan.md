# 首页轻量工作台优化方案

## 目标

将现有仅用于选择项目的首页升级为轻量的跨项目工作台，让用户能够快速判断整体测试进度、识别失败与阻塞项目、继续最近工作并创建项目，同时避免引入复杂看板和沉重的项目管理功能。

## 已确认的产品决策

1. 首页定位为跨项目工作台，而不是单纯的项目入口。
2. 项目按照当前浏览器记录的最近访问时间排序；失败和阻塞只做醒目标记，不改变排序。
3. 项目卡片展示项目名称、描述、完成度、用例总数、失败数、阻塞数和最近访问时间。
4. 顶部设置紧凑汇总栏，展示项目数、总用例数、整体完成度、失败与阻塞数量。
5. 首页提供“继续最近项目”和“新建项目”操作；没有访问记录时隐藏继续按钮。
6. 提供按项目名称和描述搜索，不增加状态筛选、标签筛选和分页。
7. 新建项目使用单个表单弹窗，一次填写名称和描述。
8. 首页采用现代、扁平、中等密度、左对齐的工作台布局，不使用大型图表、营销式 Hero 或装饰性图形。
9. 完成度口径为 `(已通过 + 未通过 + 已阻塞) / 总用例数`，用于表达执行进度，不等同于通过率。
10. 最近访问记录保存在浏览器 `localStorage`，本轮不新增用户级数据库记录。
11. 每张项目卡片右上角预留置顶、归档、删除三个图标按钮；本轮点击只提示“暂未上线”，不执行数据操作。
12. 不单独重复展示最近项目卡片；顶部快捷入口负责继续最近项目，全部项目列表按最近访问排序。

## 信息结构

1. 顶部品牌与操作区
2. 跨项目汇总栏
3. 项目搜索与项目数量
4. 项目卡片网格
5. 无项目和无搜索结果状态
6. 新建项目表单弹窗

## 数据与交互

- `/api/projects` 返回每个项目的状态聚合数据。
- 项目卡片和汇总栏使用同一份聚合数据，避免首页为每个项目分别请求用例。
- 打开项目时写入最近访问时间；直接访问项目地址也会更新记录。
- 搜索仅在浏览器端执行，不改变服务器数据。
- 创建成功后关闭弹窗、刷新项目列表并保持首页上下文。

## 本轮不做

- 置顶、归档和删除的真实数据操作
- 历史趋势、饼图、排行榜等大型可视化
- 项目标签、负责人、计划日期和权限
- 服务端最近访问记录
- 分页和高级筛选

## 验收标准

- 首页首屏能看见汇总、快捷操作、搜索和项目列表。
- 项目统计与数据库数据一致，完成度口径正确。
- 最近访问项目排在前面，继续按钮可直接进入最近项目。
- 搜索能匹配名称和描述，并提供空结果状态。
- 新建项目表单具备必填校验、提交状态和错误反馈。
- 三个预留按钮不会触发卡片跳转或修改数据。
- 桌面端和移动端无文字溢出、重叠或横向滚动。
- 原有项目概览、说明、模块和备份页面不受影响。
